# 错误处理：panic、try/except 与 Result

## 9.1 统一错误模型：panic

Scourge 没有未定义行为。整数溢出（`+ - * **` 与取负）、整数/浮点除零与取模除零、下标越界、`assert` 失败、`Result` unwrap 失败、矩阵乘维度不匹配、张量形状不兼容——一律是 **panic**：运行时错误，可被 `try/except` 捕获，未被捕获则进程以退出码 1 终止并打印诊断。

```python
def boom(a, b):
    return a // b          # b == 0 时 panic
```

参数类型在调用点单态化，返回类型由 `return` 推断。写全型 `def boom(a: int, b: int) -> int:` 同样合法，两者行为一致。

## 9.2 try/except：恰好一个裸 except

```python
def safeDiv(a, b):
    try:
        return a // b
    except:
        return -1
```

规则：

- `try` 块必须紧跟**恰好一个**裸 `except:` 子句；带类型的 `except SomeError` 不支持（E1007）；
- panic 发生在 `try` 块内 → 跳到 `except` 执行，函数继续；
- 嵌套 try 中，内层未捕获的 panic 向外层传播；
- `except` 不能获取异常对象（裸 except，无 `as e`）——panic 的诊断信息走 stderr，不属于语言内可读取的值。

嵌套传播的实测：

```python
def nestedTry():
    try:
        try:
            x = 1 // 0
            print("unreachable-inner")
        except:
            print("inner-caught")      # 内层捕获第一个 panic
        y = 1 // 0
        print("unreachable-outer")
    except:
        return "outer-caught"          # 第二个 panic 逃到外层
    return "no-panic"
```

## 9.3 assert：可带消息的断言

```python
assert n >= 0, "n 必须非负"
```

失败即 panic，可被 try/except 捕获。断言消息是文档化的手段：它进入诊断输出，帮助定位是哪个业务不变量被破坏。

## 9.4 整数溢出也是 panic

```python
def overflow():
    big = 9223372036854775807      # int64 最大值
    return big + 1                 # panic：溢出
```

这一条对从 C 来的人可能反直觉：Scourge 选择"溢出即 panic"而非回绕，与 Python 的任意精度整数不同（Scourge 是 64 位定点 int）。安全代码请用 try/except 包裹，或改用 float。

## 9.5 与 Result 的分层

两种错误处理机制的分工：

| 机制 | 语义 | 适用场景 |
|---|---|---|
| `Result[T, E]` | 错误即值，编译期强制消费（E2005） | **可预期的失败**：解析输入、边界查询、用户数据校验 |
| `panic` + `try/except` | 运行时灾难，可捕获但代表"不该发生" | **不该发生的错误**：除零、越界、溢出、断言失败 |

经验法则：函数可能因**调用方的数据**而失败 → 返回 Result；函数因**程序自身的 bug** 而失败 → panic。第 8 章的 `pct`/`safePct` 双层结构就是这条法则的样板。

## 9.6 完整示例

> **实测记录**（`t08_result.sg` 与 `t09_panic.sg`）：
> ```
> $ sg run t08_result.sg
> True
> 5
> 5
> False
> -1
> 2.5
> 42
> ok:7
> err:-1
> $ sg run t09_panic.sg
> 3
> -1
> inner-caught
> outer-caught
> b
> -999
> 42
> -1
> 0
> ```

`t08_result.sg` 源码：

```python
def parse(n: int) -> Result[int, str]:
    if n >= 0:
        return ok(n)
    return err("n 必须非负")

def checkedDiv(a: int, b: int) -> Result[float, str]:
    if b == 0:
        return err("除数为零")
    return ok(a / b)

def describe(r: Result[int, str]) -> str:
    if r.is_ok():
        return "ok:" + str(r.unwrap(0))
    return "err:" + str(r.unwrap_or(-1))

def main():
    r = parse(5)
    print(r.is_ok())            # True
    print(r.unwrap(0))          # 5
    print(r.unwrap_or(-1))      # 5
    r2 = parse(-1)
    print(r2.is_ok())           # False
    print(r2.unwrap_or(-1))     # -1
    d = checkedDiv(10, 4)
    print(d.unwrap(0.0))        # 2.5
    e: Result[int, str] = err("boom")
    print(e.unwrap(42))         # 42（err 分支取回退值）
    print(describe(parse(7)))   # ok:7
    print(describe(parse(-3)))  # err:-1
    return 0
```

局部变量由初值推断。返回 `Result` 的函数是少数仍需完整签名的地方：`ok(...)` 与 `err(...)` 的载荷类型没有可反推的上下文，省略注解会报 E2006；裸 `err` 的绑定在 AOT 还会报 E1007，所以 `e` 保留注解。

`t09_panic.sg` 源码（节选）：

```python
def outOfBounds(xs, i):
    try:
        return xs[i]            # 越界 panic 被捕获
    except:
        return "-999"

def assertCaught(n):
    try:
        return assertDemo(n)    # assert 失败 panic 被捕获
    except:
        return -1

def overflowCaught():
    try:
        return overflow()       # 溢出 panic 被捕获
    except:
        return 0

def main():
    print(safeDiv(10, 3))           # 3
    print(safeDiv(10, 0))           # -1（除零 panic 被捕获）
    print(nestedTry())              # inner-caught / outer-caught
    xs = ["a", "b", "c"]
    print(outOfBounds(xs, 1))       # b
    print(outOfBounds(xs, 9))       # -999
    print(assertCaught(21))         # 42
    print(assertCaught(-1))         # -1
    print(overflowCaught())         # 0
    return 0
```

这一组没有 Result，参数与返回类型全部自动推断，写全型（`xs: List[str]`、`-> int` 等）同样合法。
