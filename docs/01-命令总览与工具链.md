# 命令总览与工具链

## 01.1 命令总览

```
scg check <files...> [options]    静态检查（类型/形状/契约），不执行
scg interface <file> [options]    生成 .sgi 接口摘要
scg run <file> [options]          全量检查 → 编译 → 执行
scg build <file> [options]        AOT 构建：编译为原生可执行文件
scg repl                          交互式会话
scg mcp                           启动 MCP 服务器（stdio JSON-RPC）
scg version                           版本信息
```

退出码约定：**`0` 成功，`1` 诊断错误（检查失败/panic），`2` 用法错误**。

> **两种入口形态（二选一，互斥）**：① 完整骨架 `def main() -> int:`——返回值即退出码；② 脚本模式——直接写顶层语句，编译器自动合成入口（顶层 `return` 可选带退出码，裸 `return` 与省略均为 0；与 `def main` 互斥；脚本文件不可被其他模块 import）。两种形态在 `run` 与 `build` 下行为逐字节一致。
>
> **顶层赋值的模式归属（语义分界线）**：带注解的 `NAME: T = v` 恒为**模块全局声明**（0.9.7 既定形态，所有函数体可引用）；裸赋值 `x = v` 才是脚本模式语句（合成入口的局部变量，Python 手感）。处方：**函数体内要引用的顶层名必须带注解**——裸赋值被函数引用报 E2003（与 Python 模块级变量可见性差异的关键点，跨语言者注意）。

## 01.2 check：静态检查

```powershell
scg check src\main.sg src\lib.sg
scg check src\*.sg --json -j 8
```

| 选项 | 说明 |
|---|---|
| `--json` | 诊断以严格标准 JSON 输出到 stdout，供编辑器/工具消费 |
| `-j N` | 依赖分层并行检查的线程数（DAG 分层调度） |

行为要点：

- 每个文件独立做 Lexer → Parser → TypeChecker 全量检查；`import` 的依赖图按层调度，层内可并行；
- 诊断按模块名字典序统一合并输出，`-j 1` 与 `-j N` 输出逐字节一致（确定性保证）；
- 有错误时退出码 1。

JSON 诊断的形态（实测）：

```json
[{"code": "E2001","severity": "error","category": "type","message": "赋值类型不匹配：...",
  "file": "main.sg","line": 3,"col": 16,"end_line": 3,"end_col": 19,
  "fixits": [],"notes": []}]
```

`fixits` 与 `notes` 字段为将来的机器可修建议预留（当前为空数组）。错误码即契约：同一程序同一版本输出稳定，可以安全地写进 CI 断言。

## 01.3 run：编译执行

```powershell
scg run examples\hello.sg
scg run main.sg --watch
scg run main.sg --no-cache
```

| 选项 | 说明 |
|---|---|
| `--watch` | 监视模块文件变更，保存后自动重跑（mtime 轮询 + 防抖），输出做前后缀裁剪的成对 diff，超过 200 行自动截断 |
| `--no-cache` | 禁用字节码缓存，强制全量重编 |

执行管线：全量检查 → 依赖层序编译为 SG-BC 字节码 → 模块初始化 → 执行 `main`。增量缓存的五重指纹（格式版本、工具链标签、源指纹、入口、模块集）全部一致才命中；缓存损坏自愈（重编），写失败静默降级。

> **实测记录**：`build` 命令接受 `--gpu` 与 `--no-cache` 两个参数，前者启用 GPU 代码路径，后者禁用字节码缓存强制全量重编。用法：`scg build [--gpu] [--no-cache] <file.sg> [-o out.exe]`。GPU 实测与回退行为见第 16.7 节。

## 01.4 interface：生成契约

```powershell
scg interface math_utils.sg --out math_utils.sgi
```

全量验证通过后生成 `.sgi`（第 12 章）；验证失败退出码 1。`--out` 省略时输出到源文件同目录同名 `.sgi`。

## 01.5 build：AOT 构建

```powershell
scg build main.sg                 # 生成 main.exe
scg build main.sg -o out\app.exe  # 指定输出路径
```

完整管线：全量检查 → 生成 MLIR（func/arith/cf 方言；覆盖集张量 op 降级为 affine 结构化循环或 linalg 结构化 op，其余走 `@sg_*` 运行时）→ **进程内** MLIR→LLVM IR（无外部 mlir-opt/mlir-translate 依赖）→ `clang -O2` 链接内嵌 C 运行时为原生 exe。

中间产物与 exe 同目录：`<stem>.mlir`、`<stem>.ll`、`<stem>_rt.c`；任一阶段失败时诊断写入 `<stem>.buildcap`。

**双模一致**是 build 的核心纪律：AOT 产物与 `scg run` 的 stdout、panic 消息（stderr）与退出码逐字节一致（panic 文本、函数名、file:line 全对齐）。第 16 章有实测验证方法。

## 01.6 repl 与 mcp

`repl` 会话规则见第 1 章。`mcp` 在 stdio 上提供 MCP（JSON-RPC 2.0，协议版本 2024-11-05）服务器，每行一个报文，方法 `initialize` / `tools/list` / `tools/call` / `ping`。工具清单：

| 工具 | 参数 | 说明 |
|---|---|---|
| `scourge_check` | `files: string[]`、`jobs?: int` | 静态检查，返回诊断 |
| `scourge_interface` | `file: string` | 生成 .sgi 接口摘要 |
| `scourge_run` | `file: string`、`no_cache?: bool` | 执行程序，stdout/stderr 分离返回 |
| `scourge_repl_eval` | `code: string`、`reset?: bool` | 在持久 REPL 会话中求值，跨调用存活 |

最后一条对 AI 代理工作流意义重大：代理可以通过 `scourge_repl_eval` 在同一个会话里逐步构建并验证代码，跨调用保持状态——本书的测试套件本身就是用类似方式逐文件验证的。

## 01.7 文件布局速查

| 文件 | 说明 |
|---|---|
| `.sg` | 源码模块 |
| `.sgbc` | run 生成的字节码缓存（魔数/版本/源指纹，带边界校验） |
| `.sgi` | interface 生成的接口摘要 |
| `.exe` | build 生成的原生可执行文件 |
| `.mlir` / `.ll` / `_rt.c` | build 的中间产物 |
| `.buildcap` | build 失败时的诊断 |
