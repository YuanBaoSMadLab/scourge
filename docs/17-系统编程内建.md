# 系统编程内建：env/time/proc/signal

## 17.1 总览与能力门禁

系统编程内建分布在五个能力域，全部需要显式声明：

| 能力域 | 内建 | 说明 |
|---|---|---|
| `env` | `env(s)` `has_env(s)` `set_env(s,v)` `unset_env(s)` `args` | 环境变量、命令行参数 |
| `time` | `now` `epoch` `epoch_ms` `localtime(sec)` `gmtime(sec)` `sleep(ms)` | 时钟与时间 |
| `proc` | `system(cmd)` `spawn_wait(prog, argv)` | 进程 |
| `signal` | `signal_caught` `signal_reset` | 信号（Windows 控制台事件） |

纯计算时间（`now` 单调时钟）也要 `time` 域——连时钟都默认零能力，见第十九章。

## 17.2 环境变量与命令行参数（env 域）

```scourge
capability env

def main():
    set_env("MY_KEY", "v1")
    print(env("MY_KEY"))        # v1
    print(has_env("MY_KEY"))    # True
    print(len(args()))          # 命令行参数个数（不含程序名）
    print(args())               # 参数列表，如 ["a", "b", "c"]
    return 0
```

要点：

- `args` **不含程序名**，只返回用户传入的参数；`sg run x.sg a b c` 得到 `["a","b","c"]`，AOT 生成的 `.exe a b c` 同样得到 `["a","b","c"]`。
- `set_env` 返回 `bool`（是否成功）；`env` 缺失返回 `""`；`has_env` 判断是否存在。

## 17.3 时钟与时间（time 域）

```scourge
capability time

def main():
    print(epoch_ms() > 0)                       # True：毫秒时间戳
    print(len(localtime(epoch())))               # 8：本地时间拆成 8 元列表
    print(len(gmtime(epoch())))                  # 8：UTC 时间拆成 8 元列表
    t0 = now()
    # ... 计算 ...
    print(now() - t0)                            # 耗时（秒，浮点）
    return 0
```

`localtime(sec)` / `gmtime(sec)` 的参数是 **epoch 秒**（不是毫秒！），返回 8 元列表：

```
[年, 月, 日, 时, 分, 秒, 星期(0=周日), 年积日(1 起)]
```

> 避坑：`localtime` / `gmtime` 是**单参**，传 `epoch`（秒）；若误传 `epoch_ms`（毫秒）会触发 `时间值超出可表示范围` 的 panic。

## 17.4 进程（proc 域）

```scourge
capability proc

def main():
    print(system("exit 0") == 0)                # True：同步等待命令结束，返回退出码
    print(spawn_wait("cmd", ["/c", "echo", "child"]) == 0)  # True：第二参是 argv 列表
    return 0
```

- `system(cmd)`：经 shell 执行整条命令字符串，返回退出码（`int`）。
- `spawn_wait(prog, argv)`：**不经 shell**，第一个参数是程序名，第二个参数是 **`List[str]` 形式的 argv 列表**（`["/c","echo","child"]`）。启动失败可捕获，返回退出码。

> 避坑：`spawn_wait` 只有 **2 个参数**，第二个必须是 `List[str]`。写成 `spawn_wait("cmd","/c","echo","child")`（多参）会报 E2001。

## 17.5 信号（signal 域，Windows 轮询模型）

```scourge
capability signal

def main():
    # 轮询消费：SetConsoleCtrlHandler 捕获 CTRL_C / CTRL_BREAK 后置标志
    if signal_caught():
        signal_reset()       # 消费后复位，下次还可再捕获
        print("got ctrl-c")
    else:
        print("no signal")
    return 0
```

信号是**确定性轮询模型**，不是 POSIX 异步中断：脚本主动调用 `signal_caught` 检查标志，处理点静态可枚举，因此不破坏 VM/AOT 双模一致红线。仅支持 CTRL_C / CTRL_BREAK 两个控制台事件。

## 17.6 确定性红线

所有这些内建在 VM（`run`）与 AOT（`build`）下行为**逐字节一致**：`args` 的解析、`localtime` 的日历拆分、进程退出码、信号标志——双模同源。这也是它们能进"能力门禁"的前提：环境交互可声明、可复现。
