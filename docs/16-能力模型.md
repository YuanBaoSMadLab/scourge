# 能力模型

## 16.1 为什么需要能力模型

Scourge 是一门"为 AI 协同编程设计、用编译期可验证契约驾驭生成代码"的语言。AI 生成的代码最危险的地方，是它在你不知情时偷偷做了环境交互——读文件、发网络请求、调系统命令。传统语言靠人 code review 发现，Scourge 把这件事交给编译器：

**任何触达程序外世界的行为，必须在模块顶层显式声明，否则编译期直接拒绝。**

这个"程序外世界"被切成七个互不重叠的**能力域**。默认零能力，一个纯计算程序什么都不用写。

## 16.2 七域与声明语法

`capability` 语句位于模块顶层（与 `import`/`def` 同级），多个域用逗号分隔：

```scourge
capability io, net, env, proc, time, signal, ffi

def main():
    write_text("note.txt", "hello")   # io 域：写文件
    return 0
```

七个域的语义：

| 域 | 守门的内建 / 构造 | 含义 |
|---|---|---|
| `io` | `input` `read_text` `write_text` `append_text` `exists` `list_dir` | 文件系统与标准输入 |
| `net` | `net_http_get` `net_connect` `net_send` `net_recv` `net_close` `net_bind` `net_accept` `net_set_timeout` `net_udp_send` | 网络 |
| `env` | `env` `has_env` `set_env` `unset_env` `args` | 环境变量与命令行参数 |
| `proc` | `system` `spawn_wait` | 进程创建 |
| `time` | `sleep` `now` `epoch` `epoch_ms` `localtime` `gmtime` | 时钟与时间 |
| `signal` | `signal_caught` `signal_reset` | 信号（Windows 控制台事件轮询） |
| `ffi` | `@extern` 声明（全部）、`data_ptr` 地址导出 | 动态库调用 |

> **确定性红线**：能力声明对整个模块生效，不做函数级细粒度；多模块程序中各模块独立声明，运行时授予集 = 全部模块声明之并集。

## 16.3 双门禁（纵深防御）

能力有两道门，任何一道都能挡住越权调用：

**第一道——静态门禁（E5004）**。全量检查时比对"使用集 ⊆ 声明集"，未声明即报错，定位到首个使用点，`run` 与 `build` 同一门禁：

```
capability io          # 只声明了 io，没声明 time

def main():
    print(now())      # error[E5004]: 'now' 需要能力 'time'——在模块首部添加 capability time
    return 0
```

**第二道——运行期门禁**。即便有人手改字节码或 IR 绕过检查器，调用前仍会查能力位，越权直接 panic，且消息双模（VM/AOT）逐字一致：

```
panic: capability 'io' not granted (write_text) at main (main.sg:3)
```

> 实测：`read_text` 未声明 → E5004；`now` 未声明 → E5004；声明后 VM/AOT 行为完全一致。连单调时钟 `now` 都默认零能力，模型完全自洽。

## 16.4 零声明即可用的纯计算内建

下面这些内建**不触达程序外世界**（或输出结果确定性可复现），不需要任何能力声明，可直接用：

`print`、`random`/`seed`、`sha256`/`crc32`、JSON（`json_decode`）、容器/张量/数学运算（含 `min`/`max` 极值归约、`sorted`/`reversed` 列表算法）、字符串方法。

> 一句话记忆：**能力 = 环境交互**。"算"免费，"碰外面"要申请。

## 16.5 REPL 会话中的能力

REPL 中能力按会话累计：一旦某行使用（或声明）了某域，后续所有行保持授权；`capability` 声明行只增不减。这方便交互式探索，但脚本（`run`/`build`）严格按模块声明执行。

## 16.6 避坑

- **不要以为常用内建都免费**：`now`、`localtime`、`args`、`system` 都受能力门禁，写之前先想清楚它碰了哪个域。
- **能力是按域整块声明**，不能只开某个内建。需要 `net_http_get` 就开整个 `net`。
- **AOT 构建同样守门**：`build` 产物在入口处插入 `sg_cap_check`，运行期查位，与 VM 同源。
